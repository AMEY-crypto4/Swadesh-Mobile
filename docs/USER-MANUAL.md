# Swadesh CC — User Manual

How to use the platform: what each role can do, and exactly **where** in the product to do it.

> **About the data.** Telephony is simulated: there is no phone carrier behind the system, so calls, agents and SMS delivery results are generated by a built-in engine, and the screens say so (amber bar at the top). Everything else — accounts, queues, campaigns, rules, reports, API keys, webhooks, consent and privacy tools, the audit log — is real and stored in MySQL / MongoDB.

## 2. Getting started

### 2.1 Start and stop (Windows)
| Action | How |
|---|---|
| **Start** | Double-click **`Start-Demo.bat`** in the project folder. It stops any older copy, starts the databases + server, and opens Chrome and Edge on the login page when ready (about 40 seconds). **Keep the black window open.** |
| **Stop** | Close the black window, or double-click **`Stop-Demo.bat`**. |
| Developer start | `npm install` once, then `npm run dev:all` (API on `:4000`, UI with hot-reload on `:5173`). Tests: `npm test`. |

No internet is needed once installed. Data is re-created on every start.

### 2.2 The one link
**http://localhost:4000** — UI, API and live WebSocket on one port.
To open it from another computer on the same Wi-Fi/hotspot, use `http://<this-laptop's-IP>:4000` (find the IP with `ipconfig`).

### 2.3 Logging in
Open the link, choose a **company**, then either click a role button or type credentials.

| Company | Admin | Normal user | Supervisor |
|---|---|---|---|
| Aarav Insurance Services | `admin@aarav.test` | `user@aarav.test` | `supervisor@aarav.test` |
| Zenith Collections | `admin@zenith.test` | `user@zenith.test` | `supervisor@zenith.test` |
| Kaveri Healthcare | `admin@kaveri.test` | `user@kaveri.test` | `supervisor@kaveri.test` |

Password for every demo login: **`Demo@1234`**.

Each company is a separate **tenant**: its users, queues, calls, leads, keys and files are invisible to every other company.

### 2.4 The status chip
Top of every screen: **Live** (green) means the WebSocket is connected and numbers are current. **Reconnecting — data may be stale (last update Ns ago)** (amber) means the connection dropped; the screen is *not* live until it turns green again. It reconnects by itself.

## 5. Normal user guide — Agent workspace

Sign in as **Normal user**. You land on the workspace.

> **Your own seat.** The Normal-user login is shared, but every sign-in gets its own private seat (shown as **Guest XXXX · private seat** in the header). Other people on the same login cannot see or affect your status, calls or history. Seats are released when you **Sign out** or after about 10 idle minutes.

### 5.1 Screen layout
| Area | What it shows |
|---|---|
| **Header** | Live/Reconnecting chip, your name and *private seat* tag, **Sign out** |
| **My status** (left) | Your state, how long you've been in it, and the status buttons |
| **Live queue board** (left) | For each of your queues: calls waiting, agents free of staffed, longest wait, service level; below it, team counts (available / on call / wrap-up / break) and live calls. Pushed every second. |
| **Live updates** (left) | Count of WebSocket updates received and the latest few — proof the screen is fed live |
| **Main panel** (right) | Changes with your state — see 5.3 |
| **My recent calls** | Your last calls with outcome and talk time (empty for a brand-new seat) |

### 5.2 Setting your status (My status)
| Button | Meaning |
|---|---|
| **Available** | You can receive calls |
| **Break** (+ reason: Tea break / Lunch / Training / Meeting) | Not receiving calls; reason is visible to supervisors |
| **Go offline** | Signed out of the queues |

While you are ringing, on a call, in wrap-up or previewing a lead, the buttons are locked — finish the task first. If you are idle and your connection is lost for 15 seconds you are set offline automatically.

### 5.3 Handling a call
1. **Available** → wait for a call, or click **Simulate an incoming call** (a customer calling in) to try it immediately.
2. **Ringing** — the main panel shows the caller and queue. Click **Answer**. If you don't answer within 20 seconds the call returns to the queue and you are placed on Break (ring-no-answer).
3. **On call** — shows customer name/number, queue/campaign and a running timer.
   - **Recording & consent card** tells you what applies on this queue:
     - *No recording* — nothing is recorded.
     - *Consent notice played* (announce) — the configured notice was played; recording is on.
     - *Caller opted in* (opt-in) — recording is on because the caller agreed.
     - *Caller declined recording* — this call is **not** recorded.
   - **Pause recording** (shown only when recording is on and the company allows it): a **one-time resume token** appears. Copy it — it is shown once and recording cannot restart without it. Click **Copy & close**; the token is pre-filled.
   - **Resume** — enter/confirm the token and click **Resume**. A wrong token is refused and logged. (A supervisor or admin can force-resume from the Call log; that is recorded as an override.)
   - **End call**.
4. **Wrap-up** — choose a **disposition** (grouped Positive / Neutral / Negative), optionally add notes, click **Save & become available**. You receive no new calls until you save.

### 5.4 Preview campaigns
If your queue has a *Preview* campaign running, **Get next preview lead** shows a lead (name, phone). Choose **Dial** or **Skip (retry in 10 min)**.

### 5.5 Dispositions
| Positive | Neutral | Negative |
|---|---|---|
| Interested – follow up · Issue resolved · Sale closed | Already a customer · Callback requested · Information provided | Complaint raised · Do-not-call request · Not interested · Wrong number |

*Do-not-call request* and *Wrong number* feed the campaign's dialer rules (e.g. add the number to the do-not-call list).

## 6. Admin and Supervisor guide — Console

Sign in as **Admin** (or **Supervisor**). The left menu lists the pages you may use (Section 3).

### 6.1 Wallboard (`/`) — Admin, Supervisor
Live operations picture, updated over the WebSocket.
- **Tiles:** Active calls · Waiting in queue · Agents available (with busy/on-break) · Offered today · **Service level** (answered within the queue's target) · Abandoned today.
- **Queues table:** waiting, longest wait, available/staffed agents, offered, abandoned, average wait, SLA badge (green ≥ 80 %, amber ≥ 65 %, red below).
- **Dialer panel:** each running/paused campaign — mode, calls dialing, connected, abandon %. For *predictive* campaigns it shows the effective pacing and says when it has been **throttled to 1:1 to protect the abandon cap**.
- **Charts:** agents on call / available / waiting over the last 3 hours (stored in MongoDB); call volume by hour today.
- **Live calls:** direction, queue, **masked** customer number, agent, state, running duration, and recording indicator (● REC / ⏸ rec paused).

### 6.2 Agents (`/agents`) — Admin, Supervisor
**Live status tab**
- One card per agent: name, extension, state badge, time in state, calls and talk time today. Human seats are marked *human*; the rest are simulated agents.
- Filter by **state** (chips with counts) or **queue**.
- **Listen · Whisper · Barge** is shown disabled with the reason (needs a media server) — it is deliberately not faked.

**Team tab**
- Table of users with role, extension, skills, status. The shared *Normal user* login appears once as **shared login** (each sign-in is cloned from it).
- **Add user** (Admin): name, email, role (agent / supervisor), extension, skills (comma-separated), initial password (min 10 characters).
- **Disable / Enable** a user (Admin; not yourself, not another admin).

### 6.3 Queues (`/queues`) — Admin edits, Supervisor views
Table: strategy, SLA, max wait, recording mode, members, waiting now, agents free now.
**New queue / Edit** fields:
| Field | Effect |
|---|---|
| Distribution strategy | *Longest idle*, *Round robin*, *Least calls*, *Skills based*, *Ring all* — how the next agent is chosen |
| Service-level target (s) | Calls answered within this count towards SLA |
| Max wait (s) | Callers waiting longer are abandoned |
| Wrap-up (s) | Typical after-call time |
| Required skill | Only agents holding this skill are eligible |
| Recording consent | *No recording* · *Announce* (notice, then record) · *Opt-in* (record only if the caller agrees) |
| Members | Which agents serve this queue |

If someone else saved the same queue while you were editing, your save is rejected with *"Someone else changed this…"* — reload and re-apply (nothing is silently overwritten).

### 6.4 Campaigns (`/campaigns`, `/campaigns/:id`)
**List:** a card per campaign — status, queue, dialing mode, leads worked / dialable, live dialing figures.
- **Start / Resume / Pause / Complete** (Admin). *Start* is refused if there are no dialable leads or the queue has no agents. *Complete* is final.
- **New campaign:** name, queue, mode, pacing (predictive), caller ID. It is created as a **draft**; import leads, then start it.

**Dialing modes**
| Mode | Behaviour |
|---|---|
| Preview | The agent reviews each lead and chooses to dial |
| Progressive | One call per free agent (agent reserved before dialing) |
| Predictive | Dials more than one call per free agent (pacing ratio); automatically drops to 1:1 whenever the recent abandon rate exceeds the cap |

**Campaign page**
- **Tiles:** total leads, dialable now, in flight, abandon % (last 100) vs cap, effective pacing.
- **Dialer settings:** mode, pacing ratio, abandon cap (max 5 %), max attempts per lead, default retry delay, ring timeout.
- **Dialer rules:** evaluated top to bottom after every attempt; first match wins. Outcome → action:
  - *Retry after N minutes* · *Mark lead done* · *Schedule callback in N minutes* · *Add to do-not-call list*
  - Outcomes include *no answer, busy, voicemail, failed, abandoned* and dispositions such as *sale closed, callback requested, not interested, wrong number, do-not-call request*.
- **Leads:** filter by status, search phone/first name, paginated.
- **Import CSV:** header `first_name,last_name,phone,email`; phones in international format (`+91…`); numbers on the do-not-call list and duplicates are skipped; max 5,000 rows per import; you get a summary of imported / duplicate / do-not-call / invalid rows.
- The calling-window check (09:00–20:00) is switched off while simulating, and the page says so.

### 6.5 Call log (`/calls`) — Admin, Supervisor
- **Filters:** status, direction, queue, agent, exact phone number, date range → **Apply filters** / **Reset**. Filtering and paging happen on the server, so it stays fast on very large data. Refresh to see calls made since you opened the page.
- Click a call for **details**: parties, queue, campaign, agent, wait/talk/wrap times, notes, **Recording & consent** (state + every consent/pause/resume event and who did it), and the **event timeline** (kept for recent calls only).
- If recording is paused, **Override & resume** force-resumes it (logged as a supervisor override).
- Numbers of erased people show as *erased*.

### 6.6 Reports (`/reports`) — Admin, Supervisor
Choose **From / To** (or *Today / 7 days / 30 days*) and optionally a **Queue**; the date range is in company-local time.
| Tab | Shows |
|---|---|
| Overview | Totals, service level, answer / abandon / outbound-connect rates, averages, daily volume, hour-of-day profile |
| Queues | Calls, answered, abandoned, SLA %, abandon %, average/max wait, average talk |
| Agents | Handled, in/out, talk hours, average talk/wrap, positive-outcome %, sales |
| Campaigns | Dialed, connected, connect %, abandon %, no-answer/busy/voicemail, sales, leads left |
| Dispositions | Outcome mix with positive/neutral/negative |

**Export CSV** (top right) downloads the tab you are on.

### 6.7 Developer (`/developer`) — Admin
| Tab | What you can do |
|---|---|
| **API keys** | **Create key** (name, scopes, per-minute limit). The key is shown **once** — copy it; only a hash is stored. **Revoke** stops it immediately. Shows last-used time. |
| **Webhooks** | **Add endpoint** (URL + events); the signing secret is shown once. **Send test**, switch on/off, delete. 7-day delivery counts per endpoint. |
| **Delivery log** | Every webhook delivery with status, attempts, HTTP code and next retry. Filter by status, **Retry** failed ones. Refreshes every 5 seconds. |
| **API reference & try-it** | Paste a key, pick an endpoint, **Send request**; see the status, `X-RateLimit-*` headers and JSON body. Send repeatedly to see the **429** and `Retry-After`. |

### 6.8 Privacy & compliance (`/privacy`) — Admin edits, Supervisor reads the consent log
| Tab | What you can do |
|---|---|
| **Consent & retention** | Edit the consent notice wording; allow/forbid hard pause-resume of recording; set retention days for recordings, call records and SMS. **Retention preview** shows what would be purged; **Run retention now** purges (also runs automatically every 6 hours). Recordings are purged but call records stay for reporting. |
| **Consent log** | Every prompt, grant, decline, pause, resume and override, filterable by type; 14-day summary badges. |
| **Data exports** | Create an export — *Calls*, *SMS*, *Consent events* (optional date range) or *Data-subject access* (by phone). Generated in the background; **Download CSV** when *Ready*. Every request and download is audited. |
| **Erasure requests** | Enter a phone number → **Preview impact** → type the last 4 digits → **Erase permanently**. Calls are anonymised (numbers/notes/recording references removed), SMS and leads deleted, number added to do-not-call; only counts are kept as evidence. |

### 6.9 Audit log (`/audit`) — Admin
The latest 100 security- and privacy-relevant actions (who, what, target, details): user/queue/campaign changes, API keys, webhooks, exports, erasures, retention runs, recording overrides, failed resume attempts.

### 6.10 Platform showcase (`/system`) — Admin
Live, measured evidence of how the platform behaves. Each section is labelled with the capability it demonstrates.
| Section | What to do / see |
|---|---|
| **Node.js API** | Node version, memory, event-loop lag, requests/second, p50/p95/p99 latency per endpoint |
| **WebSockets** | Live frame feed, frames/s, who is connected. **Cut the connection for 8 s** really closes the socket — watch the chip go amber, then reconnect and resync. **Force resync** requests a fresh snapshot. |
| **React** | React version and render timings measured while frames stream in |
| **Heavy data** | Row counts per store; **Run benchmarks** (time and the index MySQL used for each query); **Start load test** (from the server or this browser; choose endpoint, concurrency, total) |
| **Multi-tenant** | **Run isolation probes**: tries to read other companies' rows and shows each attempt rejected |
| **Truthful UI** | What is real, simulated or unavailable, with reasons |
| **Roles & concurrent users** | The permission matrix and how simultaneous users are kept apart |

## 7. Developer API guide

Base URL: `http://localhost:4000`. All responses are JSON; errors look like `{ "error": { "code": "...", "message": "..." } }`.

**Authentication:** `Authorization: Bearer swk_live_…` (create keys in *Developer → API keys*). A key belongs to one company and can only ever see that company's data.
Seeded demo key for Aarav: `swk_live_aarav_demo_7f3a9c1e5b2d4068a1f8` (scopes below).

**Scopes:** `sms:send` · `sms:read` · `calls:write` · `calls:read`.

| Method & path | Scope | What it does |
|---|---|---|
| `GET /v1/account` | any | Key name, scopes, rate limit |
| `POST /v1/sms` `{ "to": "+91…", "body": "…" }` | `sms:send` | Queue an SMS (returns `202`; status moves queued → sent → delivered/failed) |
| `GET /v1/sms?limit=20&starting_after=<id>&status=` | `sms:read` | List messages (cursor pagination) |
| `GET /v1/sms/:id` | `sms:read` | One message |
| `POST /v1/calls` `{ "to": "+91…", "agent_id": 12 }` | `calls:write` | Click-to-call: ring a free agent and bridge the number (`agent_id` optional) |
| `GET /v1/calls`, `GET /v1/calls/:id` | `calls:read` | List / fetch calls |

**Rate limits:** per key, sliding one-minute window (default 60). Every response carries `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; beyond the limit you get **429** with `Retry-After`.
**Idempotency:** add `Idempotency-Key: <unique>` to POSTs; a replay within 24 h returns the original response with `Idempotent-Replay: true` and does not send twice.
**Do-not-call:** sending SMS or calling a number on the company's do-not-call list returns **422** `recipient_blocked`.

**Webhooks** — events: `call.completed`, `call.abandoned`, `sms.delivered`, `sms.failed`, `recording.paused`, `recording.resumed`, `webhook.test`.
Header `X-Swadesh-Signature: t=<unix>,v1=<hex>` where `v1 = HMAC-SHA256(secret, "<t>.<raw body>")`. Reject timestamps older than 5 minutes. Failed deliveries retry 5 times (5 s, 30 s, 2 min, 10 min, 1 h) and appear in the Delivery log.
In development, seeded webhooks point at a built-in verifying receiver: `GET /dev/webhook-sink/<company>/log` lists what it received (`/dev/webhook-sink/fail` always returns 500, to demonstrate retries).

Example:
```bash
curl -X POST http://localhost:4000/v1/sms \
  -H "Authorization: Bearer swk_live_aarav_demo_7f3a9c1e5b2d4068a1f8" \
  -H "Idempotency-Key: demo-001" -H "Content-Type: application/json" \
  -d '{"to":"+919876543210","body":"Your renewal is due on 12 Oct."}'
```

## 8. Working with several people at once
- **Normal users:** every sign-in = its own private seat (up to **25 per company**). If all seats are taken you are told, and a seat frees up when someone signs out or is idle for ~10 minutes.
- **Admins:** any number can work at once. Edits to the same queue/campaign are protected by version checks — the second save is refused with a clear message instead of overwriting.
- **Calls and agents:** all call/agent changes for a company are applied one at a time, so a call can never be given to two agents or answered twice.
- **Companies:** completely separate; a second window signed in to another company shows entirely different data.
- **Browsers:** a browser keeps one login at a time. Use two different browsers (e.g. Chrome + Edge) or a private window to be Admin and Normal user at the same time.

## 9. Walkthroughs

### 9.1 Two screens, one call (≈4 min)
1. **Chrome:** sign in as **Admin** → open **Agents**.
2. **Edge:** sign in as **Normal user**. In **My status** click **Available**. In Chrome the new *Guest* card turns green.
3. **Edge:** **Simulate an incoming call** → **Answer**. In Chrome open **Wallboard → Live calls**: the call appears with ● REC.
4. **Edge:** **Pause recording**, copy the token, **Resume**. Chrome shows *rec paused*, then recording again.
5. **Edge:** **End call**, choose a disposition, **Save & become available**.
6. **Chrome:** **Call log** → refresh → open the top call: disposition and the full consent trail.

### 9.2 Set up and run a campaign
1. **Queues**: check the target queue has agents and the right consent mode.
2. **Campaigns → New campaign** (draft) → open it.
3. **Leads → Import CSV**; confirm the import summary.
4. Adjust **Dialer settings** and **Dialer rules**.
5. Back on **Campaigns**, **Start**. Watch **Wallboard → Dialer** and the campaign page's live tiles; check outcomes in **Reports → Campaigns**.

### 9.3 Connect another system through the API
1. **Developer → API keys → Create key** (scopes `sms:send`, `sms:read`; limit 60). Copy it.
2. **Developer → Webhooks → Add endpoint** for `sms.delivered` and `sms.failed`; copy the secret.
3. Send an SMS with `POST /v1/sms`; watch the status change and the **Delivery log** show the signed webhook.
4. Verify the signature on your side (Section 7).

### 9.4 Handle a privacy request
1. **Privacy → Data exports → Data-subject access**: enter the phone, **Create export**, download when *Ready*.
2. **Privacy → Erasure requests**: **Preview impact**, confirm with the last 4 digits, **Erase permanently**.
3. **Audit log** shows both actions; **Call log** shows the person's calls as *erased*.

## 10. Troubleshooting
| Symptom | Cause / fix |
|---|---|
| Page won't load | The server window was closed. Run **`Start-Demo.bat`** again (≈40 s). Everyone is signed out and data is re-created. |
| Amber chip: *Reconnecting — data may be stale* | Connection dropped; it retries automatically. Numbers on screen are **not** live until the chip is green. |
| "All 25 demo seats for this company are in use" | Sign out unused Normal-user windows, or wait ~10 minutes for idle seats to free. |
| *"Your agent seat has ended. Please sign in again."* | Your seat was released (sign-out elsewhere or idle). Sign in again. |
| *"Someone else changed this while you were editing"* | Another admin saved first. Reload the page and re-apply your change. |
| *"A campaign call is already being connected to you"* | The dialer is connecting you to a customer; answer it, then try again. |
| *Set yourself Available first* | Simulated calls and preview leads need **Available** status. |
| `429 rate_limited` from the API | Over the key's per-minute limit; wait for `Retry-After` seconds. |
| Too many sign-ins (429 on login) | Limit is 20 per minute per computer; wait a minute. |
| Can't be Admin and Normal user at once | One login per browser. Use a second browser or a private window. |
| Cannot reach it from another computer | Use `http://<laptop-IP>:4000` on the same network; guest Wi-Fi often blocks device-to-device traffic — use a phone hotspot. |
| Numbers/data reset | By design: demo data is rebuilt at every start. |

## 11. Glossary
- **Tenant / company** — one customer's isolated data space.
- **Seat** — a private agent identity created for each Normal-user sign-in.
- **Queue** — a line of waiting calls served by a group of agents.
- **SLA / service level** — share of calls answered within the queue's target time.
- **Abandoned call** — a caller who hung up (or, in dialing, a connected customer with no agent free).
- **Disposition** — the agent's outcome code for a call.
- **Wrap-up** — after-call time while the agent completes the disposition.
- **Preview / Progressive / Predictive** — dialer modes (agent-initiated / one call per free agent / over-dialing with a safety cap).
- **Abandon cap** — maximum tolerated share of abandoned dialer calls; predictive pacing falls back to 1:1 above it.
- **DNC** — do-not-call list; numbers on it are never dialed or messaged.
- **Consent (announce / opt-in)** — how the caller is told about, or agrees to, recording.
- **Hard pause token** — one-time secret needed to resume a paused recording.
- **Retention** — how long recordings, call records and SMS are kept before purging.
- **Erasure** — removing a person's personal data on request.
- **WebSocket** — the always-open connection that pushes live updates to the screen.
- **Webhook** — an HTTP callback the platform sends to your system when something happens, signed so you can verify it.
